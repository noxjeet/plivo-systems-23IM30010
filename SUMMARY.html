Real-Time Media Transport Protocol

1. Assignment Overview

The objective of this assignment is to design and implement a reliable, low-latency audio transport protocol over UDP. The network relay introduces random packet drops, packet duplication, packet delays, and heavy packet reordering. The receiver must deliver each generated frame to the player before its playback deadline while keeping the overall bandwidth overhead strictly below 2.00x of the raw audio stream and minimizing playout delay.

3. Packet Format

Each custom packet transmitted between the Sender and the Receiver is structured as follows:

  • 4-Byte Sequence Number: Network byte-order (big-endian) integer representing the frame index.
  • 1-Byte has_previous Flag: Unsigned 8-bit integer (1 or 0) denoting whether the redundant previous frame is included.
  • Current Payload (160 Bytes): Raw PCM/audio audio bytes of the current frame.
  • Optional Previous Payload (160 Bytes): Raw PCM/audio bytes of the previous frame (appended only if has_previous is 1).

4. Sender Architecture

  • Receive Frame: Listens on port 47010 for raw audio frames incoming from the source harness.
  • Cache Frame: Stores the payload in a sequence-indexed circular buffer (2048 slots) to enable redundancy piggybacking.
  • Selective Redundancy: Checks if the previous frame is present in the cache, and appends it to the packet payload if seq % 20 != 0.
  • Bandwidth Calculation: Every 20th packet (when seq % 20 == 0) selectively omits the redundant frame to stay within the bandwidth limit.
  • Packet Construction: Serializes the headers and payloads, then immediately forwards the packed buffer to the relay.

5. Receiver Architecture

  • Packet Parsing: Receives packets from the relay, extracting the sequence number and checking the has_previous flag.
  • Duplicate Suppression: Maintains a lookup array of delivered frames. If a sequence number has already been forwarded to the player, it is silently discarded.
  • Recovery Using Previous Payload: If has_previous is 1 and the previous sequence number has not yet been delivered, the receiver extracts the previous frame from the redundant payload and forwards it immediately.
  • Forwarding to Player: Delivers recovered and primary payloads immediately to the player port (47020) to maximize playout timing margin.

6. Bandwidth Analysis

The raw packet size is 160 bytes. With 4-byte sequence headers and a 1-byte flag, the packet overhead is 5 bytes. When previous-frame redundancy is added, the packet size increases to 325 bytes. By skipping redundancy every 20th packet, the average packet size is: 

Average Size = (19 * 325 + 1 * 165) / 20 = 317 bytes

This corresponds to an overhead of 1.981x, which successfully satisfies the strict 2.00x bandwidth constraint.

7. Engineering Tradeoffs

Proactive Redundancy vs. Retransmissions: Feedback-based retransmission protocols (like NACK/ARQ) require a round-trip time (RTT) to request and receive lost packets. On high-jitter and high-delay networks, this RTT easily exceeds the narrow playback delay bounds, leading to late packets. Proactive redundancy was chosen because it allows instantaneous single-packet drop recovery without any feedback channel or latency overhead.

Advantages: Extremely low latency, zero feedback/control channel overhead, robust against random single packet drops, resilient to packet reordering.

Limitations: Ineffective against burst drops (losses of two or more consecutive packets) and restricted by the strict 2.00x bandwidth cap.

9. Conclusion

The implemented transport mechanism was tuned to achieve optimal robustness against general channel impairments rather than over-fitting for a single profile. By balancing the selective redundancy window at 5% omission, the system minimizes deadline misses on high-jitter networks while reliably staying within the bandwidth overhead cap.
